## 二、核心功能说明

### 2.1 试验基础数据采集

**功能描述**: 采集育种试验的基础信息,包括试验批次、作物类型、研究中心、地理位置等

**主要字段**:
- 试验ID (主键,UUID)
- 作物类型、品种名称
- 研究中心ID、程序ID、子程序ID
- 地理信息: Region、Zone、Woreda、Kebele
- GPS位置、开始日期、季节

**API端点**: `/seed/trial/base/*`

### 2.2 农民与地块属性数据采集

**功能描述**: 采集参与试验的农民信息和地块属性

**主要字段**:
- 农民姓名、性别、青年类别
- 合作社成员资格
- 地块面积、家庭ID、联系电话

**API端点**: `/seed/farmer/plot/*`

### 2.3 农事记录数据采集

**功能描述**: 记录农事管理措施,包括施肥、灌溉、除草等

**主要字段**:
- 管理措施类型
- 肥料类型和施用量
- 农药类型、灌溉类型和频率
- 除草日期、种子来源

**API端点**: `/seed/farming/record/*`

### 2.4 农艺性状数据采集

**功能描述**: 采集植物生长过程中的农艺性状数据

**主要字段**:
- 植物高度、分蘖数、穗长
- 各生育期天数(出苗、分蘖、抽穗、开花、灌浆、成熟)
- 倒伏评分、生物量
- 疾病评分、压力指标(JSON格式)
- 照片证据

**API端点**: `/seed/agronomic/trait/*`

### 2.5 环境与土壤属性数据采集

**功能描述**: 采集试验田的环境和土壤监测数据,支持IOT设备自动上传

**主要字段**:
- 土壤指标: pH值、电导率、氮磷钾含量
- 环境指标: 温度、湿度、降雨量、风速、太阳辐射
- 地貌、坡度、水源
- 时间戳

**API端点**: `/seed/environment/soil/*`

### 2.6 品种评估数据采集

**功能描述**: 采集品种的产量评估数据

**主要字段**:
- 地块ID、地块面积
- 籽粒重量、单位产量
- 含水量

**API端点**: `/seed/variety/evaluation/*`

### 2.7 实验室测试数据采集

**功能描述**: 采集种子的实验室检测数据

**主要字段**:
- 样本ID、样本状态
- 发芽率、纯度、含水量
- 蛋白质含量、毒素水平
- 种子健康发现、溯源链接
- 实验室报告文件

**API端点**: `/seed/laboratory/test/*`

## 三、技术规范

### 3.1 开发规范

✅ 遵循 `后端开发提示词.md` 中的所有规范:
- 使用 Spring Boot + MyBatis Plus 架构
- 类命名: 大驼峰式 (如 TrialBaseData)
- 方法命名: 小驼峰式 (如 selectTrialBaseDataList)
- 使用 QueryWrapper 构建查询条件
- 不创建启动类,使用 IgdpApplication
- 不使用 Swagger 注解
- 只使用 GET 和 POST 方法
- 返回类型使用 AjaxResult
- ID字段使用 String 类型,UUID主键生成策略
- 逻辑删除: del_flag (0正常, 2删除)

### 3.2 代码特点

1. **统一的CRUD接口**:
   - 查询列表: POST `/list`
   - 查询详情: GET `/{id}`
   - 新增: POST ``
   - 修改: POST `/edit`
   - 删除: POST `/delete`

2. **使用 Hutool 工具库**:
   - BeanUtil.copyProperties() 进行对象转换
   - StrUtil 进行字符串处理

3. **MyBatis Plus 增强**:
   - 继承 BaseMapper 获得基础CRUD
   - 继承 IService 获得业务层通用方法
   - 使用 @TableId 和 @TableName 注解

4. **规范的分层结构**:
   - Entity: 数据库实体映射
   - DTO: 接收前端请求参数
   - VO: 返回给前端的视图对象
   - Mapper: 数据访问层
   - Service: 业务逻辑层
   - Controller: 控制器层

## 四、使用指南

### 4.1 环境准备

1. 确保项目已启动 MySQL 数据库
2. 执行 SQL 脚本创建表:
   ```bash
   mysql -u root -p < src/main/resources/sql/seed_data_collection.sql
   ```

### 4.2 代码集成

igdp-seed 模块需要在 igdp-admin 的 pom.xml 中引入(如已引入则跳过):

```xml
<dependency>
    <groupId>com.inspur</groupId>
    <artifactId>igdp-seed</artifactId>
</dependency>
```

### 4.3 启动测试

1. 启动 IgdpApplication 主类
2. 访问接口进行测试,例如:
   - POST `http://localhost:port/seed/trial/base/list`
   - GET `http://localhost:port/seed/trial/base/{trialId}`

## 六、注意事项

1. **数据校验**: 前端需要根据API文档中的必填字段进行校验
2. **文件上传**: 照片证据和实验室报告文件需要集成文件上传功能(可使用igdp-doc模块的MinIO)
3. **JSON字段**: diseaseScore 和 stressIndicators 字段存储JSON格式数据,前后端需要约定JSON结构
4. **GPS位置**: gpsLocation 建议格式为 "经度,纬度" (如: "114.502,38.045")
5. **日期格式**: 统一使用 `yyyy-MM-dd` 或 `yyyy-MM-dd HH:mm:ss`
6. **认证授权**: 所有接口需要集成 Sa-Token 进行权限控制
