# 出库自动创建入库单功能说明

## 功能概述

当执行任何类型的出库操作时，系统会自动创建一条关联的入库单。根据出库类型的不同，入库单的处理方式也不同：

- **调拨出库（outbound_type = 2）**：自动创建 → 自动审核 → 自动入库
- **销售出库（outbound_type = 1）等其他类型**：仅创建入库单 → 需要人工审核

## 业务场景

### 场景1：仓库调拨
**业务描述**：从仓库A调拨物料到仓库B

**系统行为**：
1. 仓库A出库（扣减库存）
2. 自动创建调拨入库单
3. 自动审核通过
4. 自动执行入库（仓库B增加库存）

**优势**：一次操作完成仓库间物料转移，无需人工干预

---

### 场景2：销售出库（退货场景）
**业务描述**：销售出库后可能发生退货

**系统行为**：
1. 销售出库（扣减仓库库存）
2. 自动创建关联入库单（状态：待审核）
3. 等待人工审核
4. 审核通过后执行入库

**优势**：为可能的退货预留入库单，减少后续手工录入工作

---

## 功能对比表

| 出库类型 | 入库单类型 | 自动审核 | 自动入库 | 目标仓库来源 | 供应商类型 | 备注 |
|---------|-----------|---------|---------|-------------|-----------|------|
| 调拨出库（2） | 调拨入库（2） | ✅ 是 | ✅ 是 | outbound_object_id | 内部调拨 | 完全自动化 |
| 销售出库（1） | 采购入库（1） | ❌ 否 | ❌ 否 | outbound_object_id | 销售退货 | 需人工审核 |
| 其他类型 | 采购入库（1） | ❌ 否 | ❌ 否 | outbound_object_id | 销售退货 | 需人工审核 |

## 接口响应对比

### 1. 调拨出库响应（自动审核并入库）

```json
{
  "code": 200,
  "msg": "出库成功",
  "data": {
    "outbound_order_id": "CK202512040001",
    "updated_stock": [...],
    "batch_splits": [...],
    "inbound_order_id": "RK202512040002",
    "auto_approved": true,
    "transfer_success": true,
    "transfer_message": "调拨入库单已自动创建并完成入库"
  }
}
```

**关键字段说明：**
- `inbound_order_id`: 自动生成的入库单ID
- `auto_approved`: true（已自动审核）
- `transfer_success`: true（入库成功）
- `transfer_message`: 提示信息

---

### 2. 销售出库响应（仅创建入库单）

```json
{
  "code": 200,
  "msg": "出库成功",
  "data": {
    "outbound_order_id": "CK202512040003",
    "updated_stock": [...],
    "batch_splits": [...],
    "inbound_order_id": "RK202512040004",
    "auto_approved": false,
    "transfer_success": false,
    "transfer_message": "关联入库单已创建，等待审核"
  }
}
```

**关键字段说明：**
- `inbound_order_id`: 自动生成的入库单ID
- `auto_approved`: false（未自动审核）
- `transfer_success`: false（未入库）
- `transfer_message`: 提示等待审核

## 数据流转示例

### 示例1：调拨出库完整流程

**初始状态：**
- 仓库A（WH001）：有机肥料A 库存 1000kg
- 仓库B（WH002）：有机肥料A 库存 0kg

**步骤1：创建调拨出库单**
```http
POST /api/outbound/orders
{
  "outbound_type": 2,
  "warehouse_id": "WH001",
  "outbound_object_id": "WH002",
  "outbound_object_name": "仓库B",
  "operator": "张三",
  "details": [{
    "material_id": "M001",
    "material_name": "有机肥料A",
    "quantity": 300
  }]
}
```

**步骤2：审核通过**
```http
PUT /api/outbound/orders/CK202512040001/audit
{
  "audit_status": "approved",
  "audit_user": "李四"
}
```

**步骤3：执行出库（自动触发入库）**
```http
PUT /api/outbound/orders/CK202512040001/confirm
{
  "outbound_time": "2025-12-04 16:00:00",
  "operator": "张三"
}
```

**最终状态：**
- 仓库A（WH001）：有机肥料A 库存 700kg（-300kg）
- 仓库B（WH002）：有机肥料A 库存 300kg（+300kg）
- 出库单状态：completed
- 入库单状态：completed（自动完成）

---

### 示例2：销售出库流程

**初始状态：**
- 仓库A（WH001）：有机肥料A 库存 1000kg
- 客户仓库（CUST001）：需要记录可能的退货

**步骤1：创建销售出库单**
```http
POST /api/outbound/orders
{
  "outbound_type": 1,
  "warehouse_id": "WH001",
  "outbound_object_id": "CUST001",
  "outbound_object_name": "客户A",
  "operator": "张三",
  "details": [{
    "material_id": "M001",
    "material_name": "有机肥料A",
    "quantity": 200
  }]
}
```

**步骤2：审核通过**
```http
PUT /api/outbound/orders/CK202512040002/audit
{
  "audit_status": "approved",
  "audit_user": "李四"
}
```

**步骤3：执行出库（自动创建入库单但不入库）**
```http
PUT /api/outbound/orders/CK202512040002/confirm
{
  "outbound_time": "2025-12-04 17:00:00",
  "operator": "张三"
}
```

**中间状态：**
- 仓库A（WH001）：有机肥料A 库存 800kg（-200kg）
- 出库单状态：completed
- 入库单状态：pending（等待审核）
- 入库单ID：RK202512040005

**如果发生退货（人工操作）：**

**步骤4：审核入库单**
```http

{
  "audit_status": "approved",
  "audit_user": "王五",

}
```

**步骤5：执行入库**
```http
PUT /api/inbound/orders/RK202512040005/confirm
{
  "inbound_time": "2025-12-05 10:00:00",
  "operator": "赵六"
}
```

**最终状态：**
- 仓库A（WH001）：有机肥料A 库存 1000kg（+200kg退货）
- 入库单状态：completed

## 数据库设计

### 出库单表（outbound_order）
```sql
outbound_order_id: CK202512040001
outbound_type: 2 (调拨出库)
warehouse_id: WH001 (来源仓库)
outbound_object_id: WH002 (目标仓库/客户ID)
outbound_status: completed
```

### 入库单表（inbound_order）
```sql
inbound_order_id: RK202512040002
inbound_type: 2 (调拨入库) 或 1 (采购入库)
warehouse_id: WH002 (目标仓库)
related_order_no: CK202512040001 (关联出库单号)
supplier_id: WH001 (来源仓库/供应商)
supplier_type: "内部调拨" 或 "销售退货"
inbound_status: completed 或 pending
remark: "调拨入库 - 来自出库单：CK202512040001"
```

**关联关系：**
- 通过 `related_order_no` 字段追溯到来源出库单
- 通过 `supplier_id` 字段追溯到来源仓库
- 完整的出入库链路

const handleConfirm = async (outboundOrder) => {
  try {
    const res = await confirmOutbound(outboundOrder.outbound_order_id, {

          duration: 5000

      }

    }

  } catch (error) {

## 注意事项

### 1. 目标仓库必填
所有出库操作都必须填写 `outbound_object_id`（目标仓库ID或客户ID），否则无法创建入库单。

**错误示例：**
```
错误信息：出库对象ID不能为空
```

### 2. 目标仓库必须有效
- 目标仓库必须存在
- 目标仓库必须启用（status = '1'）

### 3. 入库单状态
- **调拨出库**：入库单状态为 `completed`
- **销售出库**：入库单状态为 `pending`（待审核）

### 4. 事务一致性
整个出库流程（包括创建入库单）在同一事务中执行，任何环节失败都会完全回滚。

### 5. 过期日期处理
入库明细的过期日期继承自出库批次的原始过期日期，确保物料保质期的准确性。

## 异常处理

### 常见异常

1. **出库对象ID不能为空**
   ```
   原因：outbound_object_id 为空
   解决：创建出库单时必须填写目标仓库ID或客户ID
   ```

2. **目标仓库不存在**
   ```
   原因：outbound_object_id 对应的仓库不存在
   解决：检查仓库ID是否正确
   ```

3. **目标仓库已停用**
   ```
   原因：目标仓库 status != '1'
   解决：启用目标仓库或更换仓库
   ```

4. **创建关联入库单失败**
   ```
   原因：入库单Service调用失败
   解决：检查入库单创建逻辑，查看详细错误日志
   ```
