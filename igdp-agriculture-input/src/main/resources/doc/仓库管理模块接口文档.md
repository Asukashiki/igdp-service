# 仓库管理模块接口文档

## 模块说明
仓库管理模块提供对农业投入品仓库的全生命周期管理，包括仓库的增删改查、容量管理、状态管理等功能。

## 基础路径
`/inventory/warehouse`

---

## 1. 查询仓库列表

### 接口说明
分页查询仓库列表，支持多条件筛选。

### 请求信息
- **接口地址**: `/inventory/warehouse/list`
- **请求方式**: `GET`
- **接口描述**: 获取仓库列表，支持按名称、编号、类型、供应商等条件筛选

### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| page | Integer | 否 | 页码，默认1 |
| pageSize | Integer | 否 | 每页数量，默认10 |
| warehouseName | String | 否 | 仓库名称(模糊查询) |
| warehouseCode | String | 否 | 仓库编号(模糊查询) |
| warehouseType | String | 否 | 仓库类型(normal/cold/dangerous) |
| supplierId | Long | 否 | 关联供应商ID |
| status | String | 否 | 状态(0-停用/1-启用) |
| keyword | String | 否 | 关键词搜索(搜索名称、编号等) |

### 请求示例

```bash
GET /inventory/warehouse/list?page=1&pageSize=10&warehouseType=normal&status=1
```

### 响应参数

| 参数名 | 类型 | 说明 |
|--------|------|------|
| code | Integer | 状态码(200-成功) |
| msg | String | 提示信息 |
| data | Object | 响应数据 |
| data.list | Array | 仓库列表 |
| data.total | Long | 总记录数 |
| data.page | Integer | 当前页码 |
| data.pageSize | Integer | 每页数量 |

### 接口说明

- **请求方式**: `POST`
- **接口描述**: 创建新仓库，系统自动生成仓库编号

### 请求参数

| 参数名 | 类型 | 必填 | 验证规则 |
|--------|------|------|----------|
| warehouseName | String | 是 | 仓库名称不能为空 |
| warehouseType | String | 是 | 仓库类型不能为空(normal/cold/dangerous) |
| location | String | 是 | 仓库位置不能为空 |
| capacity | BigDecimal | 是 | 仓库容量必须大于0 |
| belongs | String | 是 | 拥有者不能为空 |

| contactPerson | String | 否 | 联系人 |
| contactPhone | String | 否 | 联系电话 |
| remark | String | 否 | 备注 |

```json
{
  "warehouseName": "南区仓库C",
```

### 响应参数

|--------|------|------|

## 5. 删除仓库

### 接口说明
删除仓库信息（逻辑删除）。

### 请求信息
- **接口地址**: `/inventory/warehouse/delete/{warehouseId}`
- **请求方式**: `POST`
- **接口描述**: 逻辑删除仓库，设置del_flag为2

### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| warehouseId | Long | 是 | 仓库ID（路径参数） |

### 请求示例

```bash
POST /inventory/warehouse/delete/1
```

### 响应参数

| 参数名 | 类型 | 说明 |
|--------|------|------|
| code | Integer | 状态码(200-成功) |
| msg | String | 提示信息 |

### 响应示例

```json
{
  "code": 200,
  "msg": "删除成功"
}
```

**错误响应示例**:
```json
{
  "code": 500,
  "msg": "仓库不存在或已被删除"
}
```

```json
{
  "code": 500,
  "msg": "仓库存在库存，无法删除"
}
```

## 附录

### 枚举值说明

#### 仓库类型 (warehouseType)
| 值 | 说明 |
|----|------|
| normal | 普通仓库 |
| cold | 冷藏仓库 |
| dangerous | 危险品仓库 |

#### 状态 (status)
| 值 | 说明 |
|----|------|
| 0 | 停用 |
| 1 | 启用 |

### 业务规则说明

1. **仓库编号生成规则**:
   - 格式: `WH + YYYYMMDD + 3位序号`
   - 示例: `WH20251203001`
   - 系统自动生成，每天从001开始递增

2. **容量计算**:
   - 总容量(capacity): 仓库的最大存储容量
   - 已用容量(usedCapacity): 当前已使用的容量
   - 可用容量(availableCapacity): capacity - usedCapacity

3. **删除限制**:
   - 仓库存在库存时不允许删除
   - 仓库已关联入库/出库单时不允许删除
   - 使用逻辑删除，数据实际保留在数据库中

4. **容量更新**:
   - 入库时自动增加usedCapacity
   - 出库时自动减少usedCapacity
   - 不允许入库数量超过可用容量

5. **状态管理**:
   - 停用状态的仓库不允许执行入库操作
   - 停用状态的仓库可以执行出库操作（清空库存）

### 数据验证规则

1. **必填字段验证**:
   - 仓库名称、类型、位置、容量、拥有者为必填
   - 容量必须大于0

2. **唯一性验证**:
   - 仓库编号必须唯一
   - 同一供应商下仓库名称不能重复

3. **格式验证**:
   - 联系电话格式: 251开头的12位数字（埃塞俄比亚号码格式）
   - 容量字段: 最多保留2位小数

### 错误码说明

| 错误码 | 说明 |
|--------|------|
| 200 | 成功 |
| 500 | 业务异常(详见msg字段) |
| 400 | 参数验证失败 |
| 404 | 资源不存在 |

### 注意事项

1. **时间格式**: 所有时间字段格式为 `yyyy-MM-dd HH:mm:ss`
2. **分页参数**: 不传page和pageSize时使用默认值(1, 10)
3. **容量单位**: 统一使用吨(ton)或立方米(m³)，具体根据业务需求确定
4. **供应商关联**: supplierId可选，用于标识仓库归属的供应商
5. **逻辑删除**: 删除操作为逻辑删除，设置del_flag='2'
6. **状态控制**: 停用状态的仓库无法进行入库操作
7. **容量验证**: 入库时需验证是否超出可用容量
8. **联系电话**: 遵循埃塞俄比亚号码格式(251开头12位)
