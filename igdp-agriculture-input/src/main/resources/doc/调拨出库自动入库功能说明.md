# 调拨出库自动入库功能说明

## 功能概述

当执行"调拨出库"操作（`outbound_type = 2`）时，系统会自动向目标仓库创建并完成一条"调拨入库"记录，实现仓库间物料的无缝转移。

## 核心特性

### 1. 自动化流程
- ✅ 自动创建调拨入库单（`inbound_type = 2`）
- ✅ 自动审核通过入库单
- ✅ 自动执行入库操作
- ✅ 完整的库存转移
- ✅ 完整的日志记录

### 2. 数据关联
- 入库单的 `related_order_no` 字段记录来源出库单号
- 入库单的 `supplier_id` 字段记录来源仓库ID
- 入库单的 `supplier_type` 字段标记为"内部调拨"
- 完整的追溯链路

### 3. 业务规则
- **出库仓库**：库存扣减、容量释放、记录出库日志
- **入库仓库**：生成新批次、库存增加、容量占用、记录入库日志
- **过期日期**：继承自出库批次的原始过期日期
- **批次号**：入库时生成全新的批次号
- **二维码**：自动生成新的二维码

4. ✅ 仓库B入库：生成批次、增加库存、占用容量
5. ✅ 返回完整结果（包含入库单ID）

## 异常处理

### 可能的异常情况

1. **目标仓库不存在**
   ```
   错误信息：目标仓库不存在：WH002
   处理方式：抛出异常，回滚整个调拨操作
   ```

2. **目标仓库已停用**
   ```
   错误信息：目标仓库已停用，无法调拨入库
   处理方式：抛出异常，回滚整个调拨操作
   ```

3. **目标仓库容量不足**
   ```
   错误信息：仓库容量不足，当前可用容量：XXX
   处理方式：入库失败，抛出异常，回滚整个调拨操作
   ```

4. **出库对象ID为空**
   ```
   错误信息：调拨出库的目标仓库ID不能为空
   处理方式：抛出异常，回滚整个调拨操作
   ```

### 事务保证
整个调拨流程在同一个事务中执行（`@Transactional`），任何步骤失败都会完全回滚：
- ✅ 出库回滚
- ✅ 入库回滚
- ✅ 库存回滚
- ✅ 容量回滚

## 注意事项

### 1. 仅限调拨出库
此功能仅在 `outbound_type = 2`（调拨出库）时生效，销售出库（`outbound_type = 1`）不会触发自动入库。

### 2. 目标仓库必须有效
- 目标仓库必须存在
- 目标仓库必须启用（status = '1'）
- 目标仓库容量必须充足

### 3. 过期日期处理
- 优先继承出库批次的原始过期日期
- 如果无过期日期，默认设置为1年后

### 4. 批次号重新生成
入库时会生成全新的批次号，不会沿用出库批次号，确保批次的唯一性和可追溯性。

### 5. 事务一致性
整个调拨流程在同一事务中，任何环节失败都会完全回滚，保证数据一致性。
