### 1.1 查询入库单列表

**接口地址：** `GET /api/inbound/orders`

**接口描述：** 分页查询入库单列表，支持多条件筛选

### 1.3 创建入库单

**接口地址：** `POST /api/inbound/orders`

**接口描述：** 创建新的入库单，自动生成入库单ID和批次号

**请求参数：**

```json
{
  "inbound_type": 0,
  "warehouse_id": "WH001",
  "related_order_no": "SC202512040001",
  "supplier_type": "内部",
  "supplier_id": "SUP001",
  "inbound_user": "张三",
  "apply_time": "2025-12-04 10:00:00",
  "operator": "李四",
  "remark": "年度生产入库",
  "details": [
    {
      "material_id": "M001",
      "material_type": "fertilizer",
      "quantity": 500.00,
      "spec_model": "50kg/袋",
      "unit_of_measure": "kg",
      "expiry_date": "2026-12-04"
    },
    {
      "material_id": "M002",
      "material_type": "fertilizer",
      "quantity": 500.00,
      "spec_model": "25kg/袋",
      "unit_of_measure": "kg",
      "expiry_date": "2027-12-04"
    }
  ]
}
```

**字段说明：**

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| inbound_type | Integer | 是 | 入库类型：0-生产入库/1-采购入库/2-调拨入库 |
| warehouse_id | String | 是 | 入库仓库ID |
| related_order_no | String | 否 | 关联单号（生产单号/采购单号等） |
| supplier_type | String | 否 | 供应商类型 |
| supplier_id | String | 否 | 供应商ID |
| inbound_user | String | 否 | 入库员 |
| apply_time | String | 否 | 申请时间（yyyy-MM-dd HH:mm:ss） |
| operator | String | 是 | 经办人 |
| remark | String | 否 | 备注 |
| details | Array | 是 | 入库明细列表（至少一条） |
| details[].material_id | String | 是 | 投入品ID |
| details[].material_type | String | 是 | 投入品类型 |
| details[].quantity | Number | 是 | 数量 |
| details[].spec_model | String | 否 | 规格型号 |
| details[].unit_of_measure | String | 否 | 计量单位 |
| details[].expiry_date | String | 是 | 过期日期（yyyy-MM-dd） |

**响应数据：**
```json
{
  "code": 200,
  "msg": "创建成功",
  "data": {
    "inbound_order_id": "RK202512040001",
    "inbound_batch_id": "BATCH-RK202512040001"
  }
}
```

**业务规则：**
1. 入库单ID自动生成：格式为 `RK + yyyyMMdd + 流水号`
2. 入库批次号自动生成：格式为 `BATCH-RK + yyyyMMdd + 流水号`
3. 入库单创建后状态为 `pending`（待审核）
4. 需要先经过审核才能执行入库

### 1.4 审核入库单

**接口地址：** `PUT /api/inbound/orders/{inboundOrderId}/audit`

**接口描述：** 审核入库单，审核通过后才能执行入库操作

**请求参数：**

路径参数：
- `inboundOrderId`: 入库单ID

请求体：
```json
{
  "audit_status": "approved",
  "audit_user": "王五",
  "audit_time": "2025-12-04 11:00:00",
  "remark": "审核通过"
}
```

**字段说明：**

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| audit_status | String | 是 | 审核状态：approved-通过/rejected-拒绝 |
| audit_user | String | 是 | 审核人 |
| audit_time | String | 是 | 审核时间（yyyy-MM-dd HH:mm:ss） |
| remark | String | 否 | 审核意见 |

**响应数据：**
```json
{
  "code": 200,
  "msg": "审核成功"
}
```

**业务规则：**
1. 只有状态为 `pending` 的入库单才能审核
2. 审核拒绝后，入库单状态变为 `cancelled`
3. 审核通过后，才能执行入库确认操作

### 1.5 执行入库（入库确认）

**接口地址：** `PUT /api/inbound/orders/{inboundOrderId}/confirm`

**接口描述：** 执行入库操作，自动生成批次号和二维码，更新库存

**请求参数：**

路径参数：
- `inboundOrderId`: 入库单ID

请求体：
```json
{
  "inbound_time": "2025-12-04 14:00:00",
  "operator": "李四"
}
```

**字段说明：**

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| inbound_time | String | 是 | 入库时间（yyyy-MM-dd HH:mm:ss） |
| operator | String | 是 | 操作人 |

**响应数据：**
```json
{
  "code": 200,
  "msg": "入库成功",
  "data": {
    "inbound_order_id": "RK202512040001",
    "updated_stock": [
      {
        "material_id": "M001",
        "warehouse_id": "WH001",
        "batch_id": "BATCH-M001-20251204140000-001",
        "new_quantity": 500
      },
      {
        "material_id": "M002",
        "warehouse_id": "WH001",
        "batch_id": "BATCH-M002-20251204140001-002",
        "new_quantity": 500
      }
    ]
  }
}
```

**业务规则：**
1. 校验仓库是否存在且状态为启用
2. 校验仓库容量是否充足
3. 自动为每个明细生成批次号：`BATCH-{materialId}-{timestamp}-{seq}`
4. 自动生成二维码（JSON格式）包含：物料ID、批次号、仓库ID、数量、过期日期
5. 更新库存表（新增或累加库存）
6. 更新仓库已用容量
7. 记录库存变动日志
8. 更新入库单状态为 `completed`

**错误码：**
- `仓库不存在，请先配置仓库`
- `仓库已停用，无法入库`
- `仓库容量不足，当前可用容量：XXX`
- `投入品不存在：XXX`

**接口地址：** `PUT /api/inbound/orders/{inboundOrderId}/cancel`

```http

```

**响应数据：**
```json
{
  "code": 200,
  "msg": "取消成功"
}
```

**业务规则：**
1. 只有状态为 `pending` 的入库单才能取消
2. 已完成的入库单不能取消

**调拨出库响应示例（outbound_type=2，自动审核并入库）：**
```json
{
  "code": 200,
  "msg": "出库成功",
  "data": {
    "outbound_order_id": "CK202512040001",
    "updated_stock": [
      {
        "material_id": "M001",
        "warehouse_id": "WH001",
        "batch_id": "BATCH-M001-20251201100000-001",

        "remaining_quantity": 0.00
      }

      {
        "inbound_batch_id": "BATCH-M001-20251201100000-001",
        "split_quantity": 300.00,
        "remaining_quantity": 0.00
      }
    ],
    "inbound_order_id": "RK202512040002",
    "auto_approved": true,
    "transfer_success": true,
    "transfer_message": "调拨入库单已自动创建并完成入库"
  }
}
```

**业务规则（核心逻辑）：**
1. **校验库存充足性**：查询仓库中该物料的总库存是否满足出库数量
2. **校验批次有效性**：跳过已过期的批次
3. **FIFO原则扣减**：按入库时间从早到晚依次扣减库存
4. **自动批次拆分**：
   - 如果单个批次库存充足，直接从该批次扣减
   - 如果单个批次库存不足，自动拆分到多个批次
   - 记录每个批次的拆分明细到 `outbound_batch_split` 表
5. **更新库存**：扣减相应批次的库存数量
6. **更新仓库容量**：减少仓库已用容量
7. **记录变动日志**：记录每个批次的出库日志
8. **更新出库单状态**：将状态更新为 `completed`
9. **自动创建关联入库单**（🆕重要）：
   - **所有出库类型**都会自动创建关联入库单
   - 入库单的 `related_order_no` 字段记录来源出库单号
   - 入库明细与出库明细保持一致（数量、物料、规格等）
   - 过期日期继承自出库批次的原始过期日期

   **不同出库类型的处理方式：**

   - **调拨出库（outbound_type = 2）**：
     - 创建"调拨入库"单（`inbound_type = 2`）
     - ✅ 自动审核通过
     - ✅ 自动执行入库操作
     - ✅ 完成库存转移
     - 目标仓库：`outbound_object_id`
     - 供应商类型：内部调拨
     - 响应：`auto_approved = true`, `transfer_success = true`

   - **销售出库（outbound_type = 1）等其他类型**：
     - 创建"采购入库"单（`inbound_type = 1`）
     - ❌ 不自动审核（需要人工审核）
     - ❌ 不自动执行入库
     - ⏳ 入库单状态为 `pending`（等待审核）
     - 目标仓库：`outbound_object_id`
     - 供应商类型：销售退货
     - 响应：`auto_approved = false`, `transfer_success = false`

**FIFO示例：**
假设仓库中有以下批次：
- 批次A：入库时间 2025-12-01，剩余 300kg
- 批次B：入库时间 2025-12-03，剩余 700kg
- 批次C：入库时间 2025-12-04，剩余 500kg

出库 800kg 时：
1. 先从批次A扣减 300kg（批次A库存清零）
2. 再从批次B扣减 500kg（批次B剩余 200kg）
3. 批次C不动

**错误码：**
- `仓库不存在`
- `仓库已停用，无法出库`
- `库存不足，当前可用库存：XXX`
- `没有可用的有效批次（所有批次已过期）`

## 五、数据字典

### 5.1 入库类型（inbound_type）

| 值 | 名称 | 说明 |
|----|------|------|
| 0 | 生产入库 | 自有生产的投入品入库 |
| 1 | 采购入库 | 外部采购的投入品入库 |
| 2 | 调拨入库 | 从其他仓库调拨入库 |

### 5.2 出库类型（outbound_type）

| 值 | 名称 | 说明 |
|----|------|------|
| 1 | 销售出库 | 销售给客户的出库 |
| 2 | 调拨出库 | 调拨到其他仓库的出库 |

### 5.3 入库状态（inbound_status）

| 值 | 名称 | 说明 |
|----|------|------|
| pending | 待审核 | 入库单已创建，等待审核 |
| completed | 已完成 | 入库单已执行完成 |
| cancelled | 已取消 | 入库单已取消 |

### 5.4 出库状态（outbound_status）

| 值 | 名称 | 说明 |
|----|------|------|
| pending | 待审核 | 出库单已创建，等待审核 |
| completed | 已完成 | 出库单已执行完成 |
| cancelled | 已取消 | 出库单已取消 |

### 5.5 审核状态（audit_status）

| 值 | 名称 | 说明 |
|----|------|------|
| approved | 审核通过 | 审核通过，可以执行入库/出库 |
| rejected | 审核拒绝 | 审核拒绝，单据取消 |

### 5.6 库存状态（stock_status）

| 值 | 名称 | 说明 |
|----|------|------|
| normal | 正常 | 库存正常 |
| low_stock | 库存不足 | 库存低于最小库存 |
| expiring_soon | 即将过期 | 距离过期不足30天 |
| expired | 已过期 | 已超过有效期 |

### 5.7 库存操作类型（operation_type）

| 值 | 名称 | 说明 |
|----|------|------|
| inbound | 入库 | 入库操作 |
| outbound | 出库 | 出库操作 |
| adjust | 调整 | 库存调整（盘点等） |

### 5.8 仓库容量状态

| 值 | 名称 | 使用率 |
|----|------|--------|
| normal | 正常 | < 80% |
| warning | 警告 | 80% ~ 90% |
| critical | 紧急 | >= 90% |

4. **审核弹窗**

**关键代码示例（Vue 3 + Element Plus）：**

```vue
<template>

<script setup>
import { ref, reactive, onMounted } from 'vue'
import { ElMessage, ElMessageBox } from 'element-plus'
import { getInboundOrderList, auditInboundOrder, confirmInbound, cancelInboundOrder } from '@/api/inbound'

const loading = ref(false)
const inboundList = ref([])
const total = ref(0)
const queryParams = reactive({
  page: 1,
  pageSize: 20,
  inboundStatus: 'all',
  inboundType: 'all'
})

// 查询入库单列表
const handleQuery = async () => {
  loading.value = true
  try {
    const res = await getInboundOrderList(queryParams)
    inboundList.value = res.data.items
    total.value = res.data.total
  } catch (error) {
    ElMessage.error('查询失败：' + error.message)
  } finally {
    loading.value = false
  }
}

// 审核入库单
const handleAudit = async (row) => {
  ElMessageBox.prompt('请输入审核意见', '审核入库单', {
    confirmButtonText: '通过',
    cancelButtonText: '拒绝',
    distinguishCancelAndClose: true,
    inputPlaceholder: '请输入审核意见'
  }).then(async ({ value }) => {
    // 审核通过
    await auditInboundOrder(row.inbound_order_id, {
      audit_status: 'approved',
      audit_user: '当前用户',
      audit_time: new Date().toISOString().replace('T', ' ').substring(0, 19),
      remark: value
    })
    ElMessage.success('审核通过')
    handleQuery()
  }).catch(async (action) => {
    if (action === 'cancel') {
      // 审核拒绝
      const { value } = await ElMessageBox.prompt('请输入拒绝原因', '审核拒绝', {
        inputPlaceholder: '请输入拒绝原因'
      })
      await auditInboundOrder(row.inbound_order_id, {
        audit_status: 'rejected',
        audit_user: '当前用户',
        audit_time: new Date().toISOString().replace('T', ' ').substring(0, 19),
        remark: value
      })
      ElMessage.success('已拒绝')
      handleQuery()
    }
  })
}

// 执行入库
const handleConfirm = async (row) => {
  ElMessageBox.confirm('确认执行入库操作？', '提示', {
    confirmButtonText: '确认',
    cancelButtonText: '取消',
    type: 'warning'
  }).then(async () => {
    const res = await confirmInbound(row.inbound_order_id, {
      inbound_time: new Date().toISOString().replace('T', ' ').substring(0, 19),
      operator: '当前用户'
    })
    ElMessage.success('入库成功')
    // 显示批次号信息
    const batchInfo = res.data.updated_stock.map(item =>
      `物料${item.material_id}: 批次号${item.batch_id}`
    ).join('\n')
    ElMessageBox.alert(batchInfo, '批次号信息', { type: 'success' })
    handleQuery()
  })
}

onMounted(() => {
  handleQuery()
})
</script>
```

## 七、重要业务规则总结

### 7.1 入库业务规则
1. 入库单必须先审核通过才能执行入库
2. 执行入库时自动生成批次号（格式：`BATCH-{materialId}-{timestamp}-{seq}`）
3. 自动生成二维码（JSON格式包含物料、批次、仓库、数量、过期日期）
4. 入库前校验仓库容量是否充足
5. 入库后更新仓库已用容量
6. 记录库存变动日志（operation_type: inbound）

### 7.2 出库业务规则（核心）
1. 出库单必须先审核通过才能执行出库
2. **FIFO原则**：按入库时间从早到晚依次扣减库存
3. **批次拆分**：单个批次库存不足时自动拆分到多个批次
4. 跳过已过期的批次
5. 出库前校验库存总量是否充足
6. 出库后更新仓库已用容量（减少）
7. 记录批次拆分明细到 `outbound_batch_split` 表
8. 记录库存变动日志（operation_type: outbound）

### 7.3 库存预警规则
1. **低库存预警**：库存数量 < 最小库存
2. **即将过期预警**：距离过期日期 <= 30天（可配置）
3. **已过期预警**：当前日期 > 过期日期
4. **仓库容量预警**：
   - 使用率 >= 90%：紧急（critical）
   - 使用率 >= 80%：警告（warning）
   - 使用率 < 80%：正常（normal）

### 9.1 完整数据流转示例

**场景：生产入库 1000kg 有机肥，后分两次出库（600kg + 400kg）**

**步骤1：创建入库单**

```json
{
```

**步骤3：执行入库**
```json

    "new_quantity": 1000
  }]
}
```

**数据库变化：**
- `inbound_order` 表：status = "completed"
- `stock` 表：新增记录，quantity = 1000
- `stock_log` 表：记录入库日志
- `warehouse` 表：used_capacity += 1000

**步骤4：第一次出库 600kg**
```json
POST /api/outbound/orders
{
  "outbound_type": 1,
  "warehouse_id": "WH001",
  "outbound_object_id": "CUST001",
  "operator": "孙七",
  "details": [{
    "material_id": "M001",
    "quantity": 600
  }]
}

审核通过后执行出库：
PUT /api/outbound/orders/CK202512040001/confirm

响应：
{
  "updated_stock": [{
    "batch_id": "BATCH-M001-20251204140000-001",
    "outbound_quantity": 600,
    "remaining_quantity": 400
  }]
}
```

**数据库变化：**
- `stock` 表：quantity = 400（1000 - 600）
- `stock_log` 表：记录出库日志
- `warehouse` 表：used_capacity -= 600

**步骤5：假设又有新入库 500kg（批次号 BATCH-M001-20251205100000-002）**

**步骤6：第二次出库 700kg（测试FIFO和批次拆分）**
```json
POST /api/outbound/orders
{
  "details": [{
    "material_id": "M001",
    "quantity": 700
  }]
}

执行出库后的批次拆分：
{
  "batch_splits": [
    {
      "inbound_batch_id": "BATCH-M001-20251204140000-001",
      "split_quantity": 400,
      "remaining_quantity": 0
    },
    {
      "inbound_batch_id": "BATCH-M001-20251205100000-002",

      "remaining_quantity": 200
    }
  ]
```

**FIFO逻辑体现：**
1. 先从最早的批次（BATCH-001）扣减 400kg（该批次清空）
2. 再从第二批次（BATCH-002）扣减 300kg（剩余 200kg）
