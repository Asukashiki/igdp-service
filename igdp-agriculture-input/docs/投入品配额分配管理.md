# 1 投入品供应管理
## 1.1 投入品配额分配管理
### 1.1.1 奥罗米亚州投入品年度配额录入
#### 1.1.1.1 功能描述
支持奥罗米亚州按投入品类别、子类录入本年度投入品总配额量，支持多行记录批量录入，为后续 “州 - 区 - 镇 - 村 - 农民” 五级配额逐级分配提供核心基准数据。

#### 1.1.1.2 使用对象
系统管理员

#### 1.1.1.3 业务逻辑
州级操作员进入，按投入品类别（种子、化肥、农药等）、子类（如种子→小麦种子 / 玉米种子）分行录入总配额量。

#### 1.1.1.4 原型设计
查询区：支持年度搜索。

结果展示区：列表年度、投入品总量、操作时间，点击可查看详情；

详情页：按照投入品类别分别展示年度总配额。

#### 1.1.1.5 输入信息
投入品类别、年度、投入品总量

#### 1.1.1.6 输出信息
- 投入品年度配额记录
- 投入品年度配额明细记录（分投入品类别）

### 1.1.2 奥罗米亚州投入品年度配额分配
#### 1.1.2.1 功能描述
投入品年度配额分配，按照”州-区-镇-村-农民“逐级分配，由奥罗米亚州分配各区投年度配额，区级分配镇级配额。

当完成奥罗米亚州年度配额录入后，系统自动生成年度配额分配任务。

#### 1.1.2.2 使用对象
各级操作员

#### 1.1.2.3 业务逻辑
- 州级录入各区级分配额度，分配额度合计不得超过奥罗米亚州本年度配额量。
- 区级录入各镇级分配额度，分配额度合计不得超过本市当年配额。
- 镇级按照区级分配额度，依据投入品需求信息，系统按照比例分配。
- 村级按照镇级分配额度，依据投入品需求信息，系统按照比例分配。

#### 1.1.2.4 原型设计
查询区：支持年度搜索。

结果展示区：列表年度、投入品总量、操作时间，点击可查看详情；

详情页：按照投入品类别分别展示年度总配额。

#### 1.1.2.5 输入信息
投入品类别、年度、投入品总量

#### 1.1.2.6 输出信息
- 州投入品年度配额记录
- 州投入品年度配额明细记录（分投入品类别）


# 定义
- 州 - 区 - 镇 - 村 - 农民
- region - zone - worede - kebele - farmer 


# 投入品配额管理系统后端接口设计（仅用GET/POST）
## 一、接口设计原则
1. **方法约束**：仅使用`GET`（查询类接口，参数通过Query传递）和`POST`（新增/修改类接口，参数通过Request Body传递）；
2. **功能补全**：补充所有模块的“分页查询”和“单条详情查询”接口，确保数据查询覆盖“列表浏览-单条查看”全场景；
3. **层级适配**：接口权限与“州（region）-区（zone）-镇（worede）-村（kebele）-农民（farmer）”五级业务对齐，通过`operator_division_id`过滤数据范围。

  3. 执行删除：从`t_state_annual_quota`表删除该`quotaId`对应的记录（建议物理删除，若需审计可改为逻辑删除，新增`is_deleted`字段标记）。


### 模块2：投入品配额逐级分配管理（对应`t_quota_allocation`表）
#### 2.1 新增配额分配记录（POST）
- **接口路径**：`/api/quota/allocation/add`
- **请求体（Request Body）**：
  | 字段名 | 数据类型 | 是否必传 | 说明 |
  |--------|----------|----------|------|
  | year | Integer | 是 | 分配年度（与州级配额一致） |
  | categoryId | String | 是 | 投入品类别ID |
  | fromDivisionId | String | 是 | 分配方区划ID（州/区/镇/村） |
  | fromDivisionLevel | Integer | 是 | 分配方层级（1=州、2=区、3=镇、4=村） |
  | toDivisionId | String | 否 | 接收方区划ID（区/镇/村，农民接收时为空） |
  | toFarmerId | String | 否 | 接收方农民ID（农民接收时必传） |
  | allocatedQuota | BigDecimal | 是 | 单次分配量（保留2位小数） |
  | quotaId | String | 是 | 关联州级总配额ID |
  | totalReceivedQuota | BigDecimal | 是 | 分配方本级接收的总配额量 |
  | operatorId | String | 是 | 分配操作员ID |
  | operatorDivisionId | String | 是 | 操作员所属区划ID |
- **响应体（Response Body）**：
  ```json
  {
    "code": 200,
    "msg": "配额分配记录新增成功",
    "data": {
      "allocationId": "uuid-allocation-xxx",
      "allocationName": "2024_小麦种子_州（region）_奥罗米亚州_to_区（zone）_阿达玛区",
      "progressUpdateTime": "2024-05-22 09:45:00"
    }
  }
  ```
- **核心业务逻辑**：
1. **字段校验**：必传字段非空（如`year`“`categoryId`“`fromDivisionId`），`allocatedQuota`>0且保留2位小数；`toDivisionId`与`toFarmerId`二选一，且与`fromDivisionLevel`层级匹配（如村级分配仅允许`toFarmerId`非空）。
2. **量效校验**：查询分配方同年度、同类别的累计已分配量，确保“累计量+本次分配量”≤`totalReceivedQuota`（本级接收总量）；校验`totalReceivedQuota`与上级分配给本级的总量一致。
3. **权限校验**：`operatorDivisionId`对应的层级≥`fromDivisionLevel`（如区级操作员仅可操作区级分配）；`quotaId`关联的州级配额有效且年度匹配。
4. **数据生成与存储**：自动生成`allocationId`（UUID）和`allocationName`（按业务格式拼接）；计算`total_allocated_quota`“`remaining_quota`“`allocation_status`；插入表中并同步填充时间字段。

#### 2.4 修改配额分配记录（POST）
- **接口路径**：`/api/quota/allocation/update`
- **请求体（Request Body）**：
  | 字段名 | 数据类型 | 是否必传 | 说明 |
  |--------|----------|----------|------|
  | allocationId | String | 是 | 分配记录唯一标识（从分页/详情接口获取） |
  | newAllocatedQuota | BigDecimal | 是 | 修改后的单次分配量（保留2位小数，需>0） |
  | modifierId | String | 是 | 修改人ID（关联`t_system_user`） |
  | modifierDivisionId | String | 是 | 修改人所属区划ID（需与分配方层级匹配） |
- **响应体（Response Body）**：
  ```json
  {
    "code": 200,
    "msg": "配额分配记录修改成功",
    "data": {
      "allocationId": "uuid-allocation-xxx",
      "oldAllocatedQuota": 200.00, // 修改前的分配量
      "newAllocatedQuota": 250.00, // 修改后的分配量
      "updateTime": "2024-05-23 16:45:00",
      "newTotalAllocatedQuota": 250.00, // 修改后的累计分配量
      "newRemainingQuota": 750.00 // 修改后的剩余配额量
    }
  }
  ```
- **核心业务逻辑**：
  1. 字段限制：仅允许修改`allocatedQuota`（单次分配量），`fromDivisionId`、`toDivisionId`、`year`等核心字段不可修改；
  2. 量效校验：计算“原累计分配量 - 原单次分配量 + 新单次分配量”，确保结果≤`totalReceivedQuota`（本级接收总量），若超量返回错误（`code=400`，`msg="修改后累计分配量超过本级接收总量，不可修改"`）；
  3. 同步更新进度：修改`allocatedQuota`后，重新计算`total_allocated_quota`、`remaining_quota`及`allocation_status`，并更新`modifier_id`、`modifier_division_id`、`update_time`、`progress_update_time`。

  ```json
  }
  ```
- **核心业务逻辑**：
  1. 校验依赖：查询该分配记录对应的接收方（`toDivisionId`/`toFarmerId`）是否已将配额向下分配（如区接收州的配额后是否已分配给镇），若已分配返回错误（`code=400`，`msg="接收方已向下分配，不可删除"`）；
  2. 恢复配额：删除前获取原`allocatedQuota`，从分配方的`total_allocated_quota`中扣除该值，重新计算`remaining_quota`和`allocation_status`；
  3. 执行删除：从`t_quota_allocation`表删除该`allocationId`对应的记录（建议物理删除，若需审计可改为逻辑删除，新增`is_deleted`字段标记）。
