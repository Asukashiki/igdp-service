# 库存管理模块优化修改说明

## 修改日期
2025-11-26

## 修改概述
本次修改优化了库存管理模块，主要包括修复SQL错误、添加商品级别的过期日期管理、实现仓库容量校验、以及加强出入库与库存数据的联动。

---

## 一、修改内容详细说明

### 1. 修复 SQL 错误

**问题描述：**
- 接口 `/inventory/stock-in/list` 报错：`Unknown column 'ai.sku' in 'field list'`
- 原因：SQL 查询中引用了错误的列名 `ai.sku`，实际列名为 `ai.input_sku`

**修改文件：**
- `igdp-agriculture-input/src/main/resources/mapper/agriculture/inventory/StockInItemMapper.xml`

**修改内容：**
```xml
<!-- 修改前 -->

    select sii.stock_in_item_id, sii.stock_in_id, sii.input_id,
           ai.input_name, ai.sku as input_sku,
           ...
</sql>

<!-- 修改后 -->
<sql id="selectStockInItemVo">
    select sii.stock_in_item_id, sii.stock_in_id, sii.input_id,
           ai.input_name, ai.input_sku,
           ...
</sql>
```

### 2. 添加入库商品明细的过期日期字段

**业务需求：**
- 不同批次的同一商品可能有不同的过期日期
- 过期日期应在每个入库商品明细中单独设置，而不是在入库单级别统一设置

**修改文件：**

1. **数据库表结构** - `igdp-agriculture-input/sql/inv_stock_in_item.sql`
   ```sql
   -- 添加 expiry_date 字段
   `expiry_date` DATE NOT NULL COMMENT '过期日期',
   ```

2. **数据库迁移脚本** - `igdp-agriculture-input/sql/migration/add_expiry_date_to_stock_in_item.sql`
   - 创建了 ALTER TABLE 脚本用于现有数据库的升级

3. **Domain 实体** - `StockInItem.java`
   ```java
   /** 过期日期 */
   @JsonFormat(pattern = "yyyy-MM-dd")
   private Date expiryDate;
   ```

4. **DTO 类** - `StockInDTO.StockInItemDTO`
   ```java
   /** 过期日期 */
   @NotNull(message = "过期日期不能为空")
   @JsonFormat(pattern = "yyyy-MM-dd")
   private Date expiryDate;
   ```

5. **VO 类** - `StockInVO.StockInItemVO`
   ```java
   /** 过期日期 */
   @JsonFormat(pattern = "yyyy-MM-dd")
   private Date expiryDate;
   ```

6. **Mapper XML** - `StockInItemMapper.xml`
   - 更新了 SQL 查询和插入语句以包含 `expiry_date` 字段

7. **Service 实现** - `StockInServiceImpl.java`
   - 在创建入库明细时设置 `expiryDate`
   - 在确认入库创建库存记录时使用明细的 `expiryDate` 而不是入库单的 `expiredTime`

### 3. 实现仓库容量校验

**业务规则：**
- 入库时检查仓库可用容量，不足时提示预警
- 可用容量 = 仓库总容量 - 已用容量
- 入库确认时更新仓库已用容量
- 出库确认时减少仓库已用容量

**修改文件：**
- `StockInServiceImpl.java` - `confirmStockIn()` 方法

**修改内容：**
```java
// 计算总入库数量
int totalQuantity = items.stream().mapToInt(StockInVO.StockInItemVO::getQuantity).sum();

// 查询仓库信息并校验容量
Warehouse warehouse = warehouseMapper.selectById(stockIn.getWarehouseId());
if (warehouse == null || "2".equals(warehouse.getDelFlag())) {
    throw new ServiceException("仓库不存在");
}
if (!"1".equals(warehouse.getStatus())) {
    throw new ServiceException("仓库已停用");
}

// 校验仓库容量是否充足
BigDecimal usedCapacity = warehouse.getUsedCapacity() != null ? warehouse.getUsedCapacity() : BigDecimal.ZERO;
BigDecimal availableCapacity = warehouse.getCapacity().subtract(usedCapacity);
BigDecimal requiredCapacity = BigDecimal.valueOf(totalQuantity);

if (availableCapacity.compareTo(requiredCapacity) < 0) {
    throw new ServiceException(String.format("仓库容量不足，可用容量: %.2f，需要容量: %.2f",
        availableCapacity.doubleValue(), requiredCapacity.doubleValue()));
}

// ...入库逻辑...

// 更新仓库已用容量
warehouseMapper.updateUsedCapacity(stockIn.getWarehouseId(), requiredCapacity);
```

### 4. 加强出库与库存数据联动

**业务规则：**
- 创建出库单时，校验每个商品的批次库存是否充足
- 只能选择已入库且有库存的商品批次
- 出库数量不能超过批次当前库存数量
- 确认出库时扣减库存并更新仓库已用容量

**修改文件：**
- `StockOutServiceImpl.java`

**修改内容：**

1. **创建出库单时的校验** - `createStockOut()` 方法
```java
// 校验仓库是否存在
Warehouse warehouse = warehouseMapper.selectById(dto.getWarehouseId());
if (warehouse == null || "2".equals(warehouse.getDelFlag())) {
    throw new ServiceException("仓库不存在");
}
if (!"1".equals(warehouse.getStatus())) {
    throw new ServiceException("仓库已停用");
}

// 校验每个出库商品的库存是否充足
for (StockOutDTO.StockOutItemDTO itemDTO : dto.getItems()) {
    Inventory inventory = inventoryMapper.selectOrCreateInventory(
            itemDTO.getInputId(), itemDTO.getBatchNo(), dto.getWarehouseId());

    if (inventory == null) {
        throw new ServiceException(String.format("投入品ID %d 批次号 %s 在该仓库中无库存",
                itemDTO.getInputId(), itemDTO.getBatchNo()));
    }

    if (inventory.getCurrentQuantity() < itemDTO.getQuantity()) {
        throw new ServiceException(String.format("投入品ID %d 批次号 %s 库存不足，当前库存: %d，需要出库: %d",
                itemDTO.getInputId(), itemDTO.getBatchNo(),
                inventory.getCurrentQuantity(), itemDTO.getQuantity()));
    }
}
```

2. **确认出库时更新仓库容量** - `confirmStockOut()` 方法
```java
// 计算总出库数量
int totalQuantity = items.stream().mapToInt(StockOutVO.StockOutItemVO::getQuantity).sum();

// 扣减库存（现有逻辑）
for (StockOutVO.StockOutItemVO item : items) {
    // ...库存扣减逻辑...
}

// 更新仓库已用容量（减少）
BigDecimal capacityChange = BigDecimal.valueOf(-totalQuantity);
warehouseMapper.updateUsedCapacity(stockOut.getWarehouseId(), capacityChange);
```

## 二、API 接口变更说明

### 1. 入库管理接口变更

#### 1.1 创建入库单接口
- **接口路径：** `POST /inventory/stock-in`
- **请求参数变更：**

```json
{
  "warehouseId": 1,
  "supplierId": 100,
  "type": "0",
  "operator": "张三",
  "expiredTime": "2025-12-31",
  "remarks": "采购入库",
  "items": [
    {
      "inputId": 1,
      "quantity": 100,
      "expiryDate": "2025-12-31",  // 新增：每个商品明细单独设置过期日期
      "remarks": "批次备注"
    },
    {
      "inputId": 2,
      "quantity": 50,
      "expiryDate": "2026-06-30",  // 新增：不同商品可以有不同的过期日期
      "remarks": ""
    }
  ]
}
```

**重要变更：**
- `items[].expiryDate` 为新增必填字段
- 每个入库商品明细都必须指定过期日期
- 过期日期格式：`yyyy-MM-dd`

#### 1.2 入库单列表/详情接口
- **接口路径：** `GET /inventory/stock-in/list`, `GET /inventory/stock-in/{id}`
- **响应参数变更：**

```json
{
  "stockInId": "SI-20251126-0001",
  "items": [
    {
      "stockInItemId": "SI-20251126-0001-01",
      "inputId": 1,
      "inputName": "高效氯氟氰菊酯乳油",
      "inputSku": "PEST-2024-001",  // 修复：正确返回 SKU
      "quantity": 100,
      "expiryDate": "2025-12-31",  // 新增：返回商品过期日期
      "remarks": ""
    }
  ]
}
```

#### 1.3 确认入库接口
- **接口路径：** `POST /inventory/stock-in/{id}/confirm`
- **业务逻辑变更：**
  - 新增仓库容量校验
  - 仓库容量不足时返回错误：`仓库容量不足，可用容量: xxx，需要容量: xxx`
  - 确认入库成功后，更新仓库已用容量
  - 库存记录的过期日期使用商品明细的 `expiryDate` 而不是入库单的 `expiredTime`

---

### 2. 出库管理接口变更

#### 2.1 创建出库单接口
- **接口路径：** `POST /inventory/stock-out`
- **业务逻辑变更：**
  - 新增仓库状态校验（仓库必须处于启用状态）
  - 新增库存充足性校验（创建出库单时即校验库存）
  - 如果批次不存在或库存不足，立即返回错误信息

**错误响应示例：**
```json
{
  "code": 500,
  "msg": "投入品ID 1 批次号 BN-20251126-0001 库存不足，当前库存: 50，需要出库: 100"
}
```

#### 2.2 确认出库接口
- **接口路径：** `POST /inventory/stock-out/{id}/confirm`
- **业务逻辑变更：**
  - 增强库存不足的错误提示（显示当前库存和需要出库数量）
  - 确认出库成功后，更新仓库已用容量（减少）

## 三、数据库升级步骤

### 对于新部署的系统：
直接使用更新后的建表脚本：
```sql
source igdp-agriculture-input/sql/inv_stock_in_item.sql
```

### 对于已有数据的系统：
执行迁移脚本：
```sql
source igdp-agriculture-input/sql/migration/add_expiry_date_to_stock_in_item.sql
```

**注意事项：**
1. 迁移脚本会添加 `expiry_date` 字段（允许 NULL）
2. 如果有现有数据，需要手动更新过期日期值
3. 确认所有数据都有值后，可以执行脚本中注释的 `ALTER TABLE MODIFY` 语句将字段改为 NOT NULL

## 四、前端适配要点

### 1. 入库单创建/编辑页面
- 在入库商品明细表格中增加 "过期日期" 列
- 每个商品明细行都需要独立的日期选择器
- 过期日期为必填项

### 2. 入库单列表/详情页面
- 商品明细表格中显示每个商品的过期日期
- SKU 字段现在会正确返回（之前可能为空）

### 3. 出库单创建页面
- 商品选择时需要关联批次号
- 只能选择有库存的批次
- 输入数量时实时校验是否超过当前批次库存
- 建议增加批次库存数量的显示

### 4. 错误提示优化
- 仓库容量不足时，显示具体的可用容量和需要容量
- 库存不足时，显示当前库存和需要出库数量
- 批次不存在时，明确提示批次号

## 七、注意事项

1. **数据一致性：** 本次修改涉及业务逻辑变更，建议在测试环境充分测试后再部署到生产环境

2. **向后兼容性：** 新增的 `expiryDate` 字段为必填，旧的客户端调用接口会失败，需要同步更新前端

3. **数据迁移：** 已有入库记录的过期日期字段需要手动维护或通过脚本从入库单的 `expired_time` 复制

4. **性能影响：**
   - 入库确认时增加了仓库信息查询和容量计算
   - 出库创建时增加了批次库存校验
   - 对于大批量操作，需要注意性能测试

5. **错误处理：** 所有校验失败都会抛出 `ServiceException`，事务会自动回滚

## 八、后续优化建议

1. **批次号自动选择：** 出库时可以实现 FIFO（先进先出）自动选择批次

2. **容量单位：** 当前容量使用数值类型，建议增加单位字段（如：件、箱、kg 等）

3. **库存预警：** 可以增加库存不足预警阈值配置

4. **容量预警：** 可以增加仓库容量预警阈值（如：80% 时提醒）

5. **操作日志：** 建议记录容量变更的操作日志便于审计
