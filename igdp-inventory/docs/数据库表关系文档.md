## 三、表关系详细说明

### 3.1 商品与SKU关系 (1:N)

```
inventory_product (商品表)
    │
    │ 1:N (一个商品可有多个SKU规格)
    │ 关联字段: product_id
    ▼
inventory_sku (SKU表)
```

**说明**：
- 商品表存储商品基本信息（名称、分类、品牌等）
- SKU表存储商品的具体规格（如：50kg装、100kg装）
- 一个商品可对应多个SKU

---

### 3.2 仓库与库存关系 (1:N)

```
inventory_warehouse (仓库表)
    │
    ├──────────────────────────────┬──────────────────────────────┐
    │ 1:N                          │ 1:N                          │ 1:N
    ▼                              ▼                              ▼
inventory_stock              inventory_stock_batch         inventory_stock_log
(库存总表)                    (批次库存表)                   (库存流水表)
```

**说明**：
- 一个仓库可存储多种SKU商品
- 库存总表记录每个仓库每个SKU的汇总库存
- 批次库存表记录每个批次的库存明细（支持批次管理）
- 库存流水表记录所有出入库变动记录

---

### 3.3 入库单关系 (主从表 1:N)

```
inventory_inbound_order (入库单主表)
    │
    │ 1:N (一个入库单包含多个商品明细)
    │ 关联字段: inbound_id
    ▼

    ├──► inventory_warehouse (通过 warehouse_id)

    └──► inventory_sku (通过 sku_id)
```

**主表字段**：
| 字段 | 说明 |
|------|------|
| inbound_no | 入库单号（唯一） |
| warehouse_id | 入库仓库ID |
| type | 入库类型（一般入库、调拨入库） |
| status | 状态（DRAFT草稿、SUBMITTED待审批、APPROVED已入库） |
| operator | 入库操作人 |

**明细表字段**：
| 字段 | 说明 |
|------|------|
| inbound_id | 关联入库单ID |
| product_id | 商品ID |
| sku_id | SKU ID |
| main_category | 商品大类 |
| sub_category | 商品小类 |
| batch_no | 生产批次号 |
| qty | 入库数量 |
| unit | 单位 |

### 3.6 库存预警规则关系

```
inventory_warning_rule (库存预警规则表)
    │
    ├──► inventory_warehouse (通过 warehouse_id，可为空表示所有仓库)
    ├──► inventory_product (通过 product_id)
    └──► inventory_sku (通过 sku_id)
```

**说明**：

### 3.7 溯源信息关系

```
inventory_trace_info (溯源信息表)
    │
    ├──► inventory_product (通过 product_id)
    ├──► inventory_warehouse (通过 inbound_warehouse_id 入库仓库)
    └──► inventory_warehouse (通过 outbound_warehouse_id 出库仓库)
```

**说明**：
- 记录商品从入库到出库的完整流转链路
- 支持正向追踪（从源头到终端）和反向追溯（从终端到源头）

## 四、业务流程中的表关系

### 4.1 入库流程

```
1. 创建入库单
   └──► inventory_inbound_order (主表)
        └──► inventory_inbound_order_detail (明细表)

2. 审核通过后更新库存
   └──► inventory_stock (增加可用库存)
        └──► inventory_stock_batch (新增批次库存)
             └──► inventory_stock_log (记录入库流水)

3. 记录溯源信息
   └──► inventory_trace_info
```

### 4.2 出库流程

```
1. 创建出库单
   └──► inventory_outbound_order (主表)
        └──► inventory_outbound_order_detail (明细表)

2. 创建时锁定库存
   └──► inventory_stock (增加锁定库存，减少可用库存)

3. 审核通过后扣减库存
   └──► inventory_stock (扣减总库存)
        └──► inventory_stock_batch (扣减批次库存)
             └──► inventory_stock_log (记录出库流水)

4. 记录溯源信息
   └──► inventory_trace_info
```

### 4.3 盘点流程

```
1. 创建盘点单
   └──► inventory_check_order (主表)
        └──► inventory_check_order_detail (明细表)

2. 审核通过后调整库存
   └──► inventory_stock (调整库存)
        └──► inventory_stock_batch (调整批次库存)
             └──► inventory_stock_log (记录盘点调整流水)
```

## 七、数据冗余设计说明

| 表名 | 冗余字段 | 来源表 | 说明 |
|------|----------|--------|------|
| inventory_stock | product_id | inventory_product | 避免多表关联查询 |

| inventory_stock | sub_category | inventory_product | 快速筛选商品小类 |
| inventory_stock_batch | product_id | inventory_product | 避免多表关联查询 |
| inventory_stock_log | product_id | inventory_product | 流水查询优化 |
| inventory_inbound_order_detail | main_category | inventory_product | 明细展示优化 |

| inventory_outbound_order_detail | main_category | inventory_product | 明细展示优化 |

## 九、总结

本库存管理系统采用典型的主从表设计模式，核心业务围绕以下三个维度展开：

1. **空间维度**：仓库（inventory_warehouse）
2. **商品维度**：商品（inventory_product）→ SKU（inventory_sku）
3. **时间维度**：通过批次（inventory_stock_batch）和流水（inventory_stock_log）记录

业务单据（入库单、出库单、盘点单）均采用主从表结构，主表记录单据基本信息，明细表记录商品明细。通过库存总表和批次库存表实现库存的实时管理，通过库存流水表实现库存变动的全程追溯。
