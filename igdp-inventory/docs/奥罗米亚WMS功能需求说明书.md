# 仓库管理系统设计

## 1. 仓库管理系统概述
奥罗米亚智能数字农业大数据平台是一个集成化、跨部门的数字生态系统，支持研发、农业投入品管理、生产、收获后处理、物流、市场体系及金融系统等多个领域。在该生态系统中，物理仓库在价值链的多个环节均发挥着关键作用。目前，仓库分布于不同的机构和行政层级，包括：
- 奥罗米亚农业局（中央仓库和缓冲仓库）
- 奥罗米亚种子企业（种子储存仓库）
- 联盟级仓库
- 合作社级仓库
- 化肥、农药、种子及农产品专用仓库

明确仓库类型分为4类：
1、中央仓库 （用来存储化肥、农药、种子、农产品）
2、联盟仓库（用来存储化肥、农药、种子、农产品）
3、合作社仓库 （用来存储化肥、农药、种子、农产品）
4、企业仓库（用来存储种子）


一个关键的架构挑战在于，同一物理仓库可能被多个功能模块使用，例如种子繁殖管理、投入品管理、收获后管理、物流等模块。若将仓库视为特定模块的专属组件，会导致数据重复、库存记录碎片化、治理薄弱及分析能力受限等问题。

本文提供了一套清晰、可扩展且具备治理能力的设计方案，旨在通过大数据平台内的统一仓库管理系统（WMS）对所有仓库进行集中管理。

## 2. 核心设计原则
### 仓库作为共享核心服务
本设计的核心原则为：
**仓库是共享的物理资产，而非特定模块的专属实体。**
据此：
- 不得在功能模块内部独立创建或管理仓库。
- 应将统一的集中式仓库管理系统作为平台核心服务进行部署。
- 所有其他模块需通过与WMS的受控集成来引用和使用仓库资源。该方式可确保数据的单一来源、强效治理及模块间无缝分析。

## 3. 仓库管理系统的范围
仓库管理系统负责仓库的物理管理和运营管理，独立于特定行业的业务逻辑。

### 3.1 WMS的核心职责
WMS需管理以下内容：
- 仓库注册与分类
- 所有权及行政归属对齐
- 存储容量与利用率
- 库存余额
- 入库、出库及调拨流转
- 质量与认证状态
- 审计追踪与对账

## 4. 仓库注册
所有物理仓库均在中央仓库注册表中进行一次性注册。
每条仓库记录需包含以下信息：
- 唯一仓库标识
- 仓库名称
- 仓库类型（中央仓库、联盟仓库、合作社仓库、企业仓库）
- 存储类型（化肥、农药、种子、农产品，可多选）
- 所属机构（奥罗米亚农业局、联盟、合作社、奥罗米亚种子企业）
- 行政层级（省、市、县）
- 上级仓库
- 地理位置
- 存储容量
- 运营状态（活跃、停用、维护中）

仓库层级要求：
联盟和合作社仓库采用“父-子”层级结构进行管理：
- 联盟仓库作为父仓库
- 合作社仓库作为子仓库关联
- 中央或局级仓库可独立存在，或作为更高级别的父仓库

该层级结构与奥罗米亚农业局（OAB）实际的行政和运营架构保持一致。

## 6. 商品管理
### 6.1 商品管理
维护仓库库存的商品名称，以及各种属性。
商品类型需包含以下信息：
- 商品ID
- 商品名称
- 商品大类（化肥、种子、农产品、农药）
- 商量小类（化肥【氮肥、磷肥、钾肥等】、种子【玉米、小麦、苔芙、芝麻等】、农产品【玉米、小麦、苔芙、芝麻等】、农药【除虫剂、除草剂等】）
- 商品品牌
- 商品规格型号
- 单位
- 参考价格
- 生产许可证号


### 7.2 基于交易的库存控制
库存水平不得手动覆盖，所有变更均需记录为仓库交易，包括：
- 入库（收货）
- 出库（发货）
- 调拨（仓库间转移）
- 调整（审计或损耗修正）

入库单信息，包括：
- 入库单ID
- 入库类型（一般入库、调拨入库）
- 仓库id
- 业务单号（填写内容）
- 入库操作人
- 入库时间
- 备注

入库单商品明细信息，包括：
- 商品ID
- 入库单ID （关联入库单信息）
- 商品大类（化肥、种子、农产品、农药）
- 商量小类（化肥【氮肥、磷肥、钾肥等】、种子【玉米、小麦、苔芙、芝麻等】、农产品【玉米、小麦、苔芙、芝麻等】、农药【除虫剂、除草剂等】）
- 商品生产批次
- 供应商
- 数量
- 单位
- 有效期
- 入库时间【不展示】


出库单信息，包括：
- 出库单ID
- 出库类型（一般出库、调拨出库）
- 仓库id
- 接收人类型
- 接收人
- 关联业务单号（填写内容）
- 出库操作人
- 出库时间
- 备注

出库单商品明细信息，包括：
- 商品ID
- 出库单ID （关联出库单信息）
- 商品大类（化肥、种子、农产品、农药）
- 商量小类（化肥【氮肥、磷肥、钾肥等】、种子【玉米、小麦、苔芙、芝麻等】、农产品【玉米、小麦、苔芙、芝麻等】、农药【除虫剂、除草剂等】）
- 商品生产批次
- 数量
- 单位
- 出库时间【不展示】

这种基于交易的方式可确保：
- 全程可追溯性
- 审计就绪状态
- 防欺诈
- 历史数据分析
- 适用于AI的时间序列数据


## 7. 库存管理方式
### 7.1 集中式库存数据源
所有库存数量仅在WMS中维护，任何模块均不得保留独立的库存余额。
库存记录需包含以下信息：
- 仓库位置
- 存储类型（化肥、种子、农产品、农药）
- 商品ID
- 商品大类（化肥、种子、农产品、农药）
- 商量小类（化肥【氮肥、磷肥、钾肥等】、种子【玉米、小麦、苔芙、芝麻等】、农产品【玉米、小麦、苔芙、芝麻等】、农药【除虫剂、除草剂等】）
- 商品生产批次
- 有效期
- 数量
- 单位
- 质量等级
- 商品状态（可用、预留、损坏）


### 7.1 库存盘点
各仓库对库存商品进行盘点后进行盘点数据录入，录入数据需要审核，审核通过后的数据进行库存调整。
盘点单信息
- 盘点单编号
- 盘点日期
- 盘点人
- 盘点仓库
- 商品ID
- 商品大类
- 商品小类
- 商品生产批次
- 库存数据
- 实盘数据
- 差异类型（盘盈、盘亏）
- 差异数据
- 单位
- 盘点说明

盘点审核单信息
- 盘点单编号
- 盘点日期
- 盘点人
- 盘点仓库
- 商品ID
- 商品大类
- 商品小类
- 商品生产批次
- 库存数据
- 实盘数据
- 差异类型（盘盈、盘亏）
- 差异数据
- 单位
- 盘点说明
- 审核日期
- 审核人
- 审核意见


### 7.3 溯源信息管理
系统为每批入库货物生成唯一追溯码，记录从入库、出库、移库到出库的全生命周期信息，支持多维度追溯查询，确保货物来源可查、去向可追、责任可究。
每次入库、出库需要记录溯源信息，根据商品生产批次ID自动检索溯源码

溯源码信息，包括：
- 追溯码
- 商品ID
- 商品名称
- 商品生产批次
- 供应商信息
- 流转类型【出库、入库、调拨】
- 流转时间
- 操作记录ID【关联入库单ID、出库单ID】
- 入库方ID
- 入库仓库ID
- 出库方ID
- 出库仓库ID
- 追溯信息更新时间


## 9. 访问控制
基于角色的访问控制具备场景感知能力：
- 合作社仅可访问自身所属仓库
- 联盟可查看联盟及合作社仓库
- 奥罗米亚农业局（OAB）可查看所有仓库
- 奥罗米亚种子企业（OSE）仅可查看种子仓库

访问控制通过以下维度实现：
- 所属实体（owner_entity）
- 行政层级（administrative_level）
- 模块场景（module_context）

## 🌈 Color System

| Token | Color Value | Usage |
| :--- | :--- | :--- |

| Token | Color Value | Usage |
| :--- | :--- | :--- |

1.  **Hero Headings (巨型标题)**:
    *   `font-black` (900)

    *   `leading-tight`

    *   `font-black` (900)
    *   `uppercase` (全大写)

3.  **Eyebrows / Labels (眉题/标签)**:
    *   `font-bold` (700)
    *   `text-[20rpx]` - `text-[22rpx]`

    *   `text-[26rpx]` - `text-[28rpx]`
