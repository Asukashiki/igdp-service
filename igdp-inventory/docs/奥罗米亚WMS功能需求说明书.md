# 仓库管理系统设计

## 1. 仓库管理系统概述
奥罗米亚智能数字农业大数据平台是一个集成化、跨部门的数字生态系统，支持研发、农业投入品管理、生产、收获后处理、物流、市场体系及金融系统等多个领域。在该生态系统中，物理仓库在价值链的多个环节均发挥着关键作用。目前，仓库分布于不同的机构和行政层级，包括：
- 奥罗米亚农业局（中央仓库和缓冲仓库）
- 奥罗米亚种子企业（种子储存仓库）
- 联盟级仓库
- 合作社级仓库
- 化肥、农药、种子及农产品专用仓库

明确仓库类型分为4类：
1、中央仓库 （用来存储化肥、农药、种子、农产品）
2、联盟仓库（用来存储化肥、农药、种子、农产品）
3、合作社仓库 （用来存储化肥、农药、种子、农产品）
4、企业仓库（用来存储种子）


一个关键的架构挑战在于，同一物理仓库可能被多个功能模块使用，例如种子繁殖管理、投入品管理、收获后管理、物流等模块。若将仓库视为特定模块的专属组件，会导致数据重复、库存记录碎片化、治理薄弱及分析能力受限等问题。

本文提供了一套清晰、可扩展且具备治理能力的设计方案，旨在通过大数据平台内的统一仓库管理系统（WMS）对所有仓库进行集中管理。

## 2. 核心设计原则
### 仓库作为共享核心服务
本设计的核心原则为：
**仓库是共享的物理资产，而非特定模块的专属实体。**
据此：
- 不得在功能模块内部独立创建或管理仓库。
- 应将统一的集中式仓库管理系统作为平台核心服务进行部署。
- 所有其他模块需通过与WMS的受控集成来引用和使用仓库资源。该方式可确保数据的单一来源、强效治理及模块间无缝分析。

## 3. 仓库管理系统的范围
仓库管理系统负责仓库的物理管理和运营管理，独立于特定行业的业务逻辑。

### 3.1 WMS的核心职责
WMS需管理以下内容：
- 仓库注册与分类
- 所有权及行政归属对齐
- 存储容量与利用率
- 库存余额
- 入库、出库及调拨流转
- 质量与认证状态
- 审计追踪与对账

## 4. 仓库注册
所有物理仓库均在中央仓库注册表中进行一次性注册。
每条仓库记录需包含以下信息：
- 唯一仓库标识
- 仓库名称
- 仓库类型（中央仓库、联盟仓库、合作社仓库、企业仓库）
- 存储类型（化肥、农药、种子、农产品，可多选）
- 所属机构（奥罗米亚农业局、联盟、合作社、奥罗米亚种子企业）
- 行政层级（省、市、县）
- 上级仓库
- 地理位置
- 存储容量
- 运营状态（活跃、停用、维护中）

仓库层级要求：
联盟和合作社仓库采用“父-子”层级结构进行管理：
- 联盟仓库作为父仓库
- 合作社仓库作为子仓库关联
- 中央或局级仓库可独立存在，或作为更高级别的父仓库

该层级结构与奥罗米亚农业局（OAB）实际的行政和运营架构保持一致。

## 5. 仓库预警配置
仓库预警配置用于对仓库库存与容量进行阈值化管理，统一支持上限预警和下限预警，避免积压与断供风险。

### 5.1 配置对象与粒度
预警规则支持以下配置粒度：
- 仓库维度（按单仓配置）
- 仓库类型维度（中央仓库、联盟仓库、合作社仓库、企业仓库）
- 商品维度（按商品ID/SKU）
- 商品分类维度（按商品大类、商品小类）
- 全局模板维度（统一模板下发到多个仓库）

规则冲突时采用“就近优先”原则：商品维度 > 商品分类维度 > 仓库类型维度 > 全局模板维度。

### 5.2 预警规则信息
每条仓库预警规则需包含以下信息：
- 预警规则ID
- 规则名称
- 规则状态（启用、停用）
- 预警类型（上限预警、下限预警）
- 预警适用范围（仓库/仓库类型/商品/商品分类）
- 仓库ID
- 商品ID（可为空，表示按分类）
- 商品大类
- 商品小类
- 阈值类型（固定阈值、动态阈值）
- 上限阈值
- 下限阈值
- 阈值单位（件、箱、kg等）
- 预警提前量（如按下限阈值的90%提前提醒）
- 生效时间
- 失效时间
- 通知级别（一般、重要、紧急）
- 通知对象（人员、角色、部门）
- 备注

### 5.3 阈值校验规则
系统需提供以下校验能力：
- 上限阈值必须大于下限阈值。
- 阈值数值必须大于等于0。
- 阈值单位需与商品计量单位一致或存在换算关系。
- 同一适用范围内的有效规则不得重复冲突。
- 生效时间不得晚于失效时间。

### 5.4 预警触发机制
系统需支持“交易实时触发”为主、“定时批量扫描”为辅的双机制：
- 入库实时触发：每次入库提交前和入库完成后均需校验上限、下限阈值。
- 出库实时触发：每次出库提交前和出库完成后均需校验上限、下限阈值。
- 下限触发：可用库存小于等于下限阈值时触发。
- 上限触发：可用库存大于等于上限阈值时触发。
- 提前触发：库存达到提前量阈值时触发预提醒。
- 升级触发：预警在规定时限内未处理，自动升级通知。
- 定时补偿触发：系统按固定周期扫描库存，补偿交易异常或漏触发场景。

系统公告推送规则：
- 当库存超出上限阈值或低于下限阈值时，系统必须自动生成并发布系统公告。
- 同一仓库+商品在公告未关闭前不得重复发布相同级别公告。
- 库存恢复至阈值区间后，系统自动更新公告状态为“已恢复”。

预警事件需记录以下信息：
- 预警事件ID
- 触发时间
- 触发仓库
- 触发商品
- 触发库存数量
- 命中的阈值规则ID
- 预警级别
- 当前处理状态（待处理、处理中、已关闭、已忽略）
- 公告推送状态（待推送、已推送、推送失败）
- 系统公告ID

### 5.5 预警处理闭环
预警处理需形成闭环管理：
- 预警生成后自动进入待处理列表。
- 处理人可执行补货申请、调拨申请、阈值调整申请、忽略本次等动作。
- 忽略或关闭预警时必须填写处理说明。
- 处理完成后保留全量处理轨迹，支持追溯查询与统计分析。

### 5.6 预警通知与统计
系统需支持以下通知方式：
- 站内消息
- 短信（紧急级别可选）
- 邮件（可选）
- 系统公告（必选）

系统公告信息需包含以下内容：
- 公告ID
- 公告标题（仓库+商品+预警类型）
- 公告内容（当前库存、上限值、下限值、超限方向）
- 公告级别（一般、重要、紧急）
- 发布时间
- 发布范围（全员/指定角色/指定部门）
- 公告状态（已发布、已恢复、已关闭）

系统需支持以下统计能力：
- 按仓库统计预警次数
- 按商品统计预警次数
- 按预警类型统计（上限、下限）
- 按处理时效统计（平均响应时长、关闭时长）

## 6. 仓库权限分配
仓库权限分配用于对仓库“管理权”和“使用权”进行分层授权，保障仓库主数据、库存操作及跨部门协同的可控性。

### 6.1 权限模型
仓库权限分配分为两类：
- 所有权（针对人）：定义仓库责任人及是否可以编辑仓库内容。
- 使用权（针对部门）：定义部门是否可以执行入库、出库、调拨等仓库业务操作。

### 6.2 所有权（针对人）
每个仓库需指定至少1名仓库所有者，所有者信息包含：
- 仓库ID
- 所有人用户ID
- 所有人姓名
- 所有人所属机构
- 所有人生效时间
- 所有人失效时间
- 所有权状态（有效、失效）

所有权默认能力如下：
- 可编辑仓库基础信息（名称、位置、状态、容量等）
- 可维护仓库预警配置
- 可直接分配、变更、撤销本仓库的人员与部门权限
- 可查看本仓库全量操作日志与预警日志

限制规则：
- 同一时点仅允许1个“主所有者”，可配置多个“协同所有者”。
- 所有权转移由具备授权权限的人员直接执行并即时生效。
- 非所有者不得修改仓库主数据。

### 6.3 使用权（针对部门）
使用权按“部门+仓库+操作类型”进行授权，至少包含以下权限项：
- 是否允许入库
- 是否允许出库
- 是否允许仓库间调拨
- 是否允许库存调整
- 是否允许库存查看

每条使用权记录需包含以下信息：
- 使用权记录ID
- 仓库ID
- 部门ID
- 部门名称
- 权限项（入库/出库/调拨/调整/查看）
- 生效时间
- 失效时间
- 使用权状态（启用、停用）
- 分配人
- 分配时间
- 分配说明

### 6.4 授权流程
仓库权限分配采用直接授权流程：
- 新增授权：具备权限的分配人选择仓库与目标对象（人或部门）后直接授权，立即生效。
- 变更授权：具备权限的分配人直接修改权限项，旧授权自动失效并保留历史版本。
- 撤销授权：具备权限的分配人直接撤销授权，立即失效。

系统需支持临时授权，到期后自动回收权限。

### 6.5 权限校验规则
系统在入库、出库、调拨、库存调整等业务环节需实时校验权限：
- 用户是否属于被授权部门。
- 授权是否在有效期内。
- 授权状态是否为启用。
- 操作类型是否在授权范围内。

任一条件不满足时，系统需拒绝业务提交并返回明确提示信息。

### 6.6 审计与追溯
权限分配需具备审计追溯能力，至少记录：
- 授权创建、变更、撤销日志
- 授权操作日志（分配人、分配时间、分配说明）
- 权限命中日志（业务操作时的权限判定结果）

审计数据需支持按仓库、按人员、按部门、按时间区间查询。

## 7. 商品管理
### 7.1 商品管理
维护仓库库存的商品名称，以及各种属性。
商品类型需包含以下信息：
- 商品ID
- 商品名称
- 商品大类（化肥、种子、农产品、农药）
- 商量小类（化肥【氮肥、磷肥、钾肥等】、种子【玉米、小麦、苔芙、芝麻等】、农产品【玉米、小麦、苔芙、芝麻等】、农药【除虫剂、除草剂等】）
- 商品品牌
- 商品规格型号
- 单位
- 参考价格
- 生产许可证号


### 7.2 基于交易的库存控制
库存水平不得手动覆盖，所有变更均需记录为仓库交易，包括：
- 入库（收货）
- 出库（发货）
- 调拨（仓库间转移）
- 调整（审计或损耗修正）

交易阈值强校验要求：
- 每次入库都必须执行上限/下限阈值校验。
- 每次出库都必须执行上限/下限阈值校验。
- 校验时点至少包含“提交前校验”和“过账后复核”。
- 若过账后库存超出阈值，系统必须自动推送系统公告并记录预警事件。
- 若提交前已判定为严重超限风险（可配置），系统可按策略拦截单据并提示处理。

入库单信息，包括：
- 入库单ID
- 入库类型（一般入库、调拨入库）
- 仓库id
- 业务单号（填写内容）
- 入库操作人
- 入库时间
- 备注

入库单商品明细信息，包括：
- 商品ID
- 入库单ID （关联入库单信息）
- 商品大类（化肥、种子、农产品、农药）
- 商量小类（化肥【氮肥、磷肥、钾肥等】、种子【玉米、小麦、苔芙、芝麻等】、农产品【玉米、小麦、苔芙、芝麻等】、农药【除虫剂、除草剂等】）
- 商品生产批次
- 供应商
- 数量
- 单位
- 有效期
- 入库时间【不展示】


出库单信息，包括：
- 出库单ID
- 出库类型（一般出库、调拨出库）
- 仓库id
- 接收人类型
- 接收人
- 关联业务单号（填写内容）
- 出库操作人
- 出库时间
- 备注

出库单商品明细信息，包括：
- 商品ID
- 出库单ID （关联出库单信息）
- 商品大类（化肥、种子、农产品、农药）
- 商量小类（化肥【氮肥、磷肥、钾肥等】、种子【玉米、小麦、苔芙、芝麻等】、农产品【玉米、小麦、苔芙、芝麻等】、农药【除虫剂、除草剂等】）
- 商品生产批次
- 数量
- 单位
- 出库时间【不展示】

这种基于交易的方式可确保：
- 全程可追溯性
- 审计就绪状态
- 防欺诈
- 历史数据分析
- 适用于AI的时间序列数据


## 8. 库存管理方式
### 8.1 集中式库存数据源
所有库存数量仅在WMS中维护，任何模块均不得保留独立的库存余额。
库存记录需包含以下信息：
- 仓库位置
- 存储类型（化肥、种子、农产品、农药）
- 商品ID
- 商品大类（化肥、种子、农产品、农药）
- 商量小类（化肥【氮肥、磷肥、钾肥等】、种子【玉米、小麦、苔芙、芝麻等】、农产品【玉米、小麦、苔芙、芝麻等】、农药【除虫剂、除草剂等】）
- 商品生产批次
- 有效期
- 数量
- 单位
- 质量等级
- 商品状态（可用、预留、损坏）


### 8.2 库存盘点
各仓库对库存商品进行盘点后进行盘点数据录入，录入数据需要审核，审核通过后的数据进行库存调整。
盘点单信息
- 盘点单编号
- 盘点日期
- 盘点人
- 盘点仓库
- 商品ID
- 商品大类
- 商品小类
- 商品生产批次
- 库存数据
- 实盘数据
- 差异类型（盘盈、盘亏）
- 差异数据
- 单位
- 盘点说明

盘点审核单信息
- 盘点单编号
- 盘点日期
- 盘点人
- 盘点仓库
- 商品ID
- 商品大类
- 商品小类
- 商品生产批次
- 库存数据
- 实盘数据
- 差异类型（盘盈、盘亏）
- 差异数据
- 单位
- 盘点说明
- 审核日期
- 审核人
- 审核意见


### 8.3 溯源信息管理
系统为每批入库货物生成唯一追溯码，记录从入库、出库、移库到出库的全生命周期信息，支持多维度追溯查询，确保货物来源可查、去向可追、责任可究。
每次入库、出库需要记录溯源信息，根据商品生产批次ID自动检索溯源码

溯源码信息，包括：
- 追溯码
- 商品ID
- 商品名称
- 商品生产批次
- 供应商信息
- 流转类型【出库、入库、调拨】
- 流转时间
- 操作记录ID【关联入库单ID、出库单ID】
- 入库方ID
- 入库仓库ID
- 出库方ID
- 出库仓库ID
- 追溯信息更新时间


## 9. 访问控制
基于角色的访问控制具备场景感知能力：
- 合作社仅可访问自身所属仓库
- 联盟可查看联盟及合作社仓库
- 奥罗米亚农业局（OAB）可查看所有仓库
- 奥罗米亚种子企业（OSE）仅可查看种子仓库

访问控制通过以下维度实现：
- 所属实体（owner_entity）
- 行政层级（administrative_level）
- 模块场景（module_context）

## 🌈 Color System

### Primary Palette (核心色盘)

| Token | Color Value | Usage |
| :--- | :--- | :--- |
| `bg-base` | `#F5F7F4` | **页面主背景**。温暖的灰绿色，替代纯白，护眼且自然。 |
| `primary` | `#009A44` | **主品牌色**。用于按钮、图标高亮、强调文字。 |
| `primary-dark` | `#004d22` | **深色背景**。用于Header、重要板块背景，传递稳重感。 |
| `primary-light` | `#E8F5E9` | **浅色背景**。用于装饰元素、次级按钮背景。 |

### Text Colors (文本颜色)

| Token | Color Value | Usage |
| :--- | :--- | :--- |
| `text-main` | `#1A1A1A` | **主要标题**。深黑，高对比度。 |
| `text-secondary` | `#64748B` | **正文/次要信息**。蓝灰色，现代且柔和。 |
| `text-muted` | `#94A3B8` | **辅助信息/标签**。浅灰色。 |
| `text-inverse` | `#FFFFFF` | **反色文本**。用于深色背景上。 |

## 📝 Typography System

排版强调**粗细对比**和**字母间距**的运用。

### Patterns

1.  **Hero Headings (巨型标题)**:
    *   `font-black` (900)
    *   `text-[48rpx]` - `text-[56rpx]`
    *   `tracking-tight` (紧凑)
    *   `leading-tight`

2.  **Section Headings (区块标题)**:
    *   `font-black` (900)
    *   `uppercase` (全大写)
    *   `tracking-tight`

3.  **Eyebrows / Labels (眉题/标签)**:
    *   `font-bold` (700)
    *   `text-[20rpx]` - `text-[22rpx]`
    *   `uppercase`
    *   `tracking-widest` (极宽间距, 0.2em - 0.3em)

4.  **Body Text (正文)**:
    *   `text-[26rpx]` - `text-[28rpx]`
    *   `leading-relaxed` (宽松行高)
